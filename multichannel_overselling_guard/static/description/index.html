Overview

Selling the same physical unit through a POS register, a website storefront, and a B2B portal at once is exactly how retailers end up overselling: each channel checks stock against its own view of the world, with no idea what the other two are doing at the same moment. Overselling Guard for Multi-Channel Retail closes that gap with a lightweight soft-reservation mechanism — the instant an order line lands on a website or B2B cart, or a POS order syncs to the backend, a short-lived hold is placed on that stock so the other channels' availability checks see it too. A configurable reserved buffer per product/warehouse adds extra headroom for fast-moving SKUs, opt-in per product category so it only applies where it actually matters. And because no soft-hold mechanism can promise zero race conditions, a safety-net check runs at order confirmation: if two channels still manage to both claim the last unit, the second confirmation is flagged for manual review instead of being silently accepted — or blocked and reversed. It's built for the small-to-mid retailer running Website, POS and a B2B portal on one Odoo instance who needs cross-channel stock sanity without a message broker or a rewrite of checkout.

A safety net that flags, never blocks

Most anti-overselling tooling either hard-blocks a checkout the moment stock looks tight, or says nothing until the delivery fails. Overselling Guard takes a third path: the soft reservation is the primary defense, and the safety-net check that runs at order confirmation only ever flags a race-condition oversell for a manager to review — the sale itself is never silently reversed or rejected out from under a customer.

  • No surprise checkout failures from an overzealous hard block
  • Every flagged case lands in one review queue with the requested vs. available quantities attached
  • A direct "View Order" link from the alert straight to the sale or POS order in question

Guarding that's opt-in, not one-size-fits-all

Not every SKU in a catalog is at real risk of being oversold. Guarding is enabled per product category, so a retailer can turn it on for the handful of fast-moving, limited-stock lines that actually need cross-channel protection, and leave the long tail of slow-moving inventory running exactly as it did before installing the module — no buffer, no soft reservations, no extra overhead.

  • A category toggle plus a default reserved buffer, inherited down the category tree
  • Ungated products keep behaving like plain on-hand stock, unchanged
  • A per-product/warehouse buffer overrides the category default where needed
